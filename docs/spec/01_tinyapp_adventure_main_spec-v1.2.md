- **확정 규칙:** 사용자가 승인한 구조·정책. 구현 담당자가 임의 변경하지 않는다.

## 1. 개요

- 분류: 카드형 어드벤처 + 턴제 배틀. 학습 개념은 비교·논리 연산자, 조건식(if, switch), 확률 판정.
- 컨셉: 의뢰를 받은 용사가 3일 동안 Java·JS·TS 세 언어 지역을 돌며 이벤트와 몬스터를 만나고 의뢰품을 구해 귀가한다.
- 핵심: "코드를 제대로 읽은 사람이 기대값에서 이긴다." 판단에 필요한 현재 변수·조건·확률은 코드로 보여 주고 선택지에 성공률을 따로 표시하지 않는다. 운은 결과를 흔들지만 기대값은 코드 읽기에 따라 달라진다.
- 레퍼런스: 모험가 이야기, 프린세스 메이커 2 무사수행, Arrow a Row, 랜덤 인카운트 TRPG 기획안.
- 게임 앱 자체는 정적 앱. 게임 규칙·콘텐츠·그래픽은 앱 코드로 제공한다. 공식 SDK 세션/점수 계약을 유지한다. 밸런스 분석은 별도 관리 기능으로 추가하고 데이터 저장·연동 방식은 CHK 12에서 확인한다.
- 명세의 두 층: §4~§8 필수 기준선, §11-1 선택 확장. 점수·판 길이·종료 조건·기획 규칙을 바꾸는 확장은 담당자 재량이 아니다.

## 2. 앱 구성과 개발 스택

- **스택:** Vite + React + TypeScript. 빌드 결과물(`dist`)을 레포에 커밋한다 (메인스펙 앱 규격).
- **빌드 경로:** Vite `base: './'`(상대 경로) 필수. 서빙 방식의 세부는 김 `02_01` 확정에 맞춘다.
- **콘텐츠 데이터:** 몹·아이템·이벤트·미션은 앱 안의 데이터 파일(JSON 또는 TS)로 포함한다. 브라우저 저장소는 사용하지 않는다.
- **그래픽 에셋 (바이너리 없는 앱)**
  - AI로 그린 그림을 허의 `이미지투픽셀코드` 유틸로 **TS 런 데이터**(팔레트 + 런 길이 인코딩)로 변환해 코드로 포함한다. 이미지 파일을 쓰지 않는다.
  - 앱은 런 데이터를 **세로 병합한 SVG 사각형**으로 그린다. 확대해도 선명하고(`shape-rendering="crispEdges"`), 팔레트를 인자로 받아 낮밤 색을 바꿀 수 있다. 변환은 앱 안의 **변환 메서드 하나**가 맡는다(런 → 가로 줄 → 같은 폭·색의 줄을 세로 병합 → 사각형). 에셋마다 한 번만 계산하고 결과를 재사용한다. 에셋 제작 쪽은 TS 런 데이터까지만 넣는다.
  - 유틸의 SVG 내보내기는 사용하지 않는다. 현재 픽셀마다 사각형을 만들어 무겁다(테스트 기준 256px 나무 1그루: SVG 내보내기 약 1.4MB·사각형 17,333개 / TS 런 약 3KB·런 184개 / 세로 병합 SVG 약 1.8KB·사각형 28개).
  - 그림 하나는 메서드(또는 컴포넌트) 하나로 분리한다.
  - 스타일은 **페이퍼아트**. 색이 적고 면이 단순할수록 사각형 수가 줄어, 스타일과 성능이 같은 방향을 향한다. 적은 색과 넓은 단색 면을 쓰되, 작은 카드에서도 알아볼 수 있도록 실루엣과 비례를 다듬는다.
  - **원본 규격:** 기본은 64×64(지물·카드·몹·아이템·이펙트). 이벤트 그림과 큰 지형만 128×128. 모두 투명 PNG.
  - **표시 배율:** 게임 플레이 장면의 에셋(길·지형지물·몹·아이템 등)은 화면에서 픽셀 한 칸의 크기가 같도록 같은 배율로 표시한다. 원경의 산, 타이틀 배경, UI 아이콘은 용도에 맞는 예외 배율로 표시한다.
  - **재사용:** 에셋당 TS 런 데이터는 한 벌. 길 위의 카드와 모달이 같은 데이터를 쓴다.
  - **아이템 등급 표현:** 아이템 그림은 등급과 상관없이 한 장. 빛나는 = 작은 반짝임 3개(`eff-loot-burst`를 축소)를 아이템 위 가장자리에 얹고 투명도로 번갈아 반짝이게 함. 일반 = 그대로. 부서진 = 공용 금간 오버레이 그림 한 장을 아이템 모양으로 잘라(clip) 얹고 팔레트를 살짝 탁하게.
  - **지역 화풍:** 에셋 카테고리는 공유하고, 지역마다 지형·지물의 형태를 다르게 잡는다. 팔레트는 지역별 3벌을 두고, 밤은 같은 팔레트에 CSS 필터로 톤을 낮춘다.
  - **색 규칙:** 팔레트 교체가 안정적으로 동작하도록, 같은 역할의 색(예: 잎사귀 초록, 바위 회색)은 에셋끼리 같은 색값으로 칠한다. 안티앨리어싱(반투명·중간색 가장자리)은 쓰지 않는다.
  - **용사 그림 없음:** 화면이 곧 용사의 시야다(1인칭).
  - **제작 흐름:** 원본 PNG 제작 → `이미지투픽셀코드`로 TS 런 추출 → 앱에서 팔레트 적용과 움직임 구현.
- 플랫폼 공식 기록은 점수만 제출한다. 신규 플레이 분석 데이터는 점수 제출과 분리하며, 어드민 ON/OFF 및 플랫폼 계약을 별도 확정한다(§8, §10).

## 4. 게임 규칙

### 4-1. 판·진행·시작 흐름

- 30장 참여 고정. 낮 5장 + 밤 5장 = 하루/지역. 총 3일, 낮밤 6구간.
- 지역 순서는 판 시작 시 Java·JS·TS를 셔플. 세 지역이 정확히 한 번씩 10장씩 등장한다.

| 구간 | 참여 카드 | 지역 |
| --- | --- | --- |
| 1일차 낮·밤 | 1~10 | 3개 언어 중 랜덤 |
| 2일차 낮·밤 | 11~20 | 남은 2개 중 랜덤 |
| 3일차 낮·밤 | 21~30 | 남은 1개 |

- 지역 전환 및 낮밤 전환은 실제 참여 수로 계산한다. 패스하면 게이지·일차·시간대는 진전되지 않고 실제 시간은 계속 흐른다.
- 전체 제한시간 N분(실측 후 확정). 출발할 때 안내하고 HUD 카운트다운 표시. 고민·패스·연출 중에도 시간이 흐른다.
- 시작: 타이틀 → 스탯 굴림(무제한 리롤) → 의뢰자에게 미션 1개 랜덤 배정(리롤 없음) → 출발(이 순간 SDK 세션 시작) → 카드 길.
- 회차 간 상태 이어짐 없음. 직접 스탯 배분·인벤토리·연습 모드·일시정지·사운드 없음(기존 기본값 유지).

### 4-2. 유저 스탯

- HP 포인트, 공격, 방어 총 30포인트 랜덤 배분. 각 최소 5포인트(기존 초기값).
- 감마 분포 가중치(α=2 초기값). v1.1 시뮬레이션(20만회) 스탯당 평균 10, 최빈값 9, 5 약 1.1%, 20 약 0.002%. 정수화는 최대 잉여 방식, 동률 hp→attack→defense.
- **시작 최대 HP = HP 포인트 ×100 (v1.2 초기값).** 현재 HP는 최대치로 시작. 기존 코드 HP_PER_POINT=10(TEMP)은 이번 초기값과 다름. CHK 08에서 환산 비율과 피해량을 종합 테스트한다.
- 스탯 영구 변화는 기본값에 누적, 임시 효과는 별도 계층. 최종 계산의 마지막에 정한 하한값으로 clamp. 하한은 테스트로 확정. 영구 디버프를 받더라도 기존 임시 효과는 유지된다.
- 스탯 계산의 소수점 처리: 내부 소수 첫째 자리 유지 및 표시 반올림은 논의된 방식(최종 검증 대상). 특히 음수·0.5 처리와 명중/피해 계산에서 사용되는 실수·표시값의 구분은 CHK 08에서 확정. 임의로 올림/내림 정책 확정 금지.

| 유형 | 배분 경향 | 특징 | 대가 |
| --- | --- | --- | --- |
| 버서커형 | 공격 높음 | 빠르게 끝냄, 밤에 강함 | 맞으면 아픔 |
| 탱커형 | 방어 높음 | 버티며 카운터를 노림, 낮에 강함 | 피해를 주는 속도가 느림 |
| 생존형 | HP 높음 | 명중·회피 확률 높고 오래 버팀 | 전투가 길어져 시간 소모 |

### 4-3. 전투 진입·도망·분기·게이지

**전투 진입 전과 전투 중을 구분한다.** 도망은 전투 전만 허용. 전투 시작 후에는 도망 버튼을 제공하지 않는다.

| 상황 | 선택 / 처리 | 게이지 |
| --- | --- | --- |
| 일반 깨어 있는 몹 | 싸운다 / 도망간다. 도망은 유저 명중률을 이용해 판정 | 싸움/도망 실패 +1, 성공 +0 |
| 기습 | 몹 선공, 선택 없이 강제 전투 | +1 |
| 잠든 몹 | 깨워서 싸운다 / 몰래 지나간다. 실패는 깨워서 싸우는 경로와 동일 | 전투 +1, 몰래 통과 성공 +0 |
| 확정 패스 가능한 상태 이벤트 | 지나간다 | +0 |
| 출렁다리 | 돌파한다 / 지나간다. 돌파는 참여, 지나가기는 패스 | 돌파 +1, 지나가기 +0 |
| 출렁다리 지나가기 이후 몹 조우 | 이어서 강제 전투. 추가 도망 없음 | 전투 +1 (다리에는 +0) |
| 갈림길 | 왼쪽 / 오른쪽. 패스·전투 없음 | +1 |
| 수상한 상자 실패 | 같은 카드에서 미믹 전투 | 이벤트+전투 합쳐 +1 |

- 일반 몹 조우의 일반:기습 비율은 **70:30**. 이미 전투가 강제되는 이벤트·실패 경로에 다시 도망/기습을 추첨해서 이중 회피 기회를 만들지 않는다. 잠든 몹과 이벤트 강제 전투의 선공 세부는 기존 유저 선공을 기준으로 유지하며 CHK 08에서 확인한다.
- 일반 전투: 나→몹→나→몹… . 기습: 몹→나→몹→나… . 기습은 첫 유저 차례를 건너뛴 형태이며 전투 엔진은 공통.
- 명중률 원식: 자기 현재 HP / (유저 현재 HP + 몹 현재 HP). 유저 도망 성공률 = 유저 명중률, 원식에서 1−몹 명중률과 같음. 하한·상한 적용 시 대칭/보완관계가 깨지지 않도록 함께 검증. 유저 명중률과 몹 명중률을 별도의 회피 스탯으로 중복 계산하지 않는다.
- 한 카드에 연결된 배틀은 하나의 참여 단위. 출렁다리 패스 후 강제 배틀은 다리 +0, 배틀 +1. 연출상 이어 보여도 게이지 중복 증가 금지.
- 카드 풀 랜덤, 같은 카드 연속 출현 금지. 배틀 포함 이벤트에 이어지는 전투는 같은 경로로 처리하고 무관하게 다음에 나오는 몹은 다음 카드. 분기에서 나오는 일반 몹은 해당 시간대 출현 풀에서 선택.
- 참여 카드는 전투·보상·결과 처리를 마쳐 버려지기 전에 다음 카드로 전환한다. 전투 진입 시 참여를 확정하되, 낮밤·지역 변경/귀가 질문/30장 종료는 해당 카드 처리 완료 후 적용.

### 4-4. 배틀 행동·판정

| 상태 | 공격 | 방어 | 차지 |
| --- | --- | --- | --- |
| 평상시 | 일반 공격 | 받는 피해 감소 | 차지 상태 진입 |
| 차지 중 | 차지공격(배율 2배 초과 가안) | 카운터(패링 100%, 자신 피해 0, 공격자에게 반사) | 불가(연속 차지 금지) |

- 유저·몹 공통 행동/판정 메서드. 몹 행동은 가중치 랜덤, 몹의 차지 상태는 공개하고 예정 행동은 숨긴다. 차지는 다음 자기 행동에 소비한다.
- 공격 명중 실패: 헛스윙, 피해 0. 명중: 빗맞힘 0.5배 / 평타 1.0배 / 크리티컬 1.x배(기존 초기 규칙: 명중 후 등급 균등 추첨, 배율·확률은 테스트).
- 피해 기본식 = (공격력−방어력) × 타격 등급 배율 × (해당 시 차지 배율). 명중 시 최소 피해 1. 방어 감소율 등 설정값은 CHK 08.
- 카운터: 공격한 쪽이 자기 공격을 자기 방어력으로 받음. 반사량 = (공격자의 공격력−공격자 자신의 방어력) × 등급 배율 × (차지 배율); 명중한 경우 최소 1, 헛스윙이면 0.
- 선공 순서와 틱은 v1.2 교대 행동 기준으로 변경한다. v1.1의 양쪽 동시 행동 선정/라운드 시작 HP 스냅샷·유저 결과 우선 규칙은 그대로 복제하지 않는다. 방어/카운터의 상대 차례 적용·소모, 각 행동에서 명중률 갱신과 사망/틱 경계는 CHK 08에서 기존 효과를 보존하는 실행 순서를 검증한다. HP 0이면 추가 행동 불가. 무승부 처리 등 경계값은 전투 테스트에서 확인하되 기존 판 종료 조건을 유지한다.
- 모든 행동 종료에 틱 처리(§4-7). 시간 초과 시 게임오버. 타격 등급, 실제 피해량, 차지·카운터 결과는 점수·미션 품질·보상에 필요한 데이터로 기록.

### 4-5. 몹 종류·스탯·출현

- 일반 8종(낮 방어형 2, 낮 균형형 2, 밤 공격형 2, 밤 균형형 2) + 미믹 1종. 미믹은 수상한 상자 실패에서만 등장. 레코드 하나=몹 하나=활동 시간대 하나(미믹은 공통 예외).
- 몹 기본 스탯 범위 내 랜덤 추출 → 지역 보정 → 방문 순번 배율. 식: (기본 스탯 + 지역별 보정) × 방문 순번 배율.
- 지역별 고유 강점은 몹마다 다름. 예: 늑대 Java 방어, JS 공격, TS HP. 방문 순번은 언어와 무관.
- 몹 HP 기준선: 평균 HP 10포인트 용사와 붙으면 초기 명중률 약 50%가 되도록 조율. HP에 투자한 유저가 명중·도망에 이점을 얻는다.
- 낮에는 방어형·균형형, 밤에는 공격형·균형형. 낮/밤 균형형은 다른 레코드.
- 잠든 몹은 공용 그림자 에셋으로 정체를 가린다. 깨어날 때 8종 중 하나가 등장. 실제 몹의 활동 시간과 현재 시간대를 비교하여 잠 깊이를 결정.

| 상황 | 잠 깊이 | 몰래 지나가기 | 깨운 몹 |
| --- | --- | --- | --- |
| 자신의 활동 시간에 잠 | 선잠 | 성공률 낮음 | 덜 강함 |
| 자신의 휴식 시간에 잠 | 깊은 잠 | 성공률 높음 | 더 강함 |

- 코드에 확률을 표시해 깊이를 간접적으로 추론할 수 있게 한다. 잠 깊이·보정·등장 비율은 테스트 변수.
- 선행 v1.1의 길목을 지키거나 건드리면 깨어나는 등장 방식은 삭제 지시가 없으므로 보존하되, 실제 선택지는 확정된 전투 전 2지선다 공통 구조에 연결한다. 추가 연출·분류 세부는 CHK 08.

### 4-6. 미션템과 전투 보상

**미션템과 보상템은 별개. 미션템에 랜덤 버프를 부여하지 않는다.**

#### 자동 수집

- 배틀 미션의 대상 몹 처치 시 의뢰용 미션템 1개 자동 수집. 보상 선택에 영향을 받지 않으며 버프 효과 없음.
- 일반 몹이 미션 대상이 아닌 경우에는 전용 미션템을 수집하지 않는다. 상자는 별도 경로(§4-8).
- 배틀 미션의 미션템 품질은 **대상 몹을 처치한 마지막 유효 피해(막타)의 타격 분류에 따른 확률 추첨**으로 정한다. 전투 중 차지 크리티컬이 한 번 발생했다는 사실만으로 빛나는 등급이 확정되지는 않는다. 아래 '막타 기반 등급 추첨' 가중치를 미션템에도 동일하게 적용한다.
- 상자 경로의 품질은 별도: 직접 열기 성공은 빛나는, 미믹 경유는 일반·부서진만. 배틀 품질 판정과 중복 적용하여 두 개를 수집하지 않는다.
- 미션 대상과 수량은 §5. 수집 개수는 요구량을 넘겨도 누적.

#### 선택 보상

| 몹/경로 | 보상 선택지 A | 보상 선택지 B |
| --- | --- | --- |
| 공격형 | 공격 버프템 | 피템 1종 |
| 방어형 | 방어 버프템 | 피템 1종 |
| 균형형 | 피템 1종 | 서로 다른 피템 1종 |
| 미믹(일반 경로) | 금빛 자물쇠(스코어템) | 피템 |
| 미믹(상자 탐색 미션 진행 중) | 공방 버프템(상자 보상안) | 피템 |

- 항상 **2개 중 택 1**을 기본으로 한다. 피템은 고정적으로 선택지에 포함. 균형형에는 공방 버프가 없음. 선택 효과는 즉시 적용; 인벤토리 없음.
- 미믹의 금빛 자물쇠 스코어템은 선택해야 점수 획득, 즉시 반영 후 소멸. 자동으로 점수 지급하지 않는다. 미션용 자물쇠와 스코어용 자물쇠는 역할 분리. 탐색 미션 중에는 스코어용 자물쇠 등장 금지.
- 탐색 미션의 미믹 공방/피 선택은 앞선 논의의 연결안으로 기록하며, 상자 미션 자동 수집과 충돌하지 않게 CHK 08에서 통합 검증한다. 해당 경로의 공방 종류 추첨은 조율 대상.
- 미믹 경로의 등급은 빛나는 제외. 일반/부서진만 적용. 일반 몹의 피템은 등급 3종 추첨 대상이 아님.

#### 막타 기반 등급 추첨 — 미션템 품질·전투 선택 보상

| 등급 | 효과 | 지속시간 |

- **배틀 미션템 품질과 등급이 있는 전투 선택 보상에 같은 막타 유형별 확률 가중치를 적용한다.** 둘은 서로 다른 획득물이다. 미션템은 대상 처치 시 자동 수집하며 버프가 없고, 선택 보상은 별도 선택 후 효과를 적용한다. 차지 크리티컬 막타는 빛나는 확률을 높일 뿐 빛나는를 확정하지 않는다.

- 비율은 이전 논의에서 확정한 초기 가중치. 미믹은 빛나는를 제외하고 각각 일반:부서진 5:3, 4:3, 4:4로 재정규화. 자물쇠 점수·공방 버프·상자 미션템의 경로별 적용 범위는 같은 등급 추첨기와 연동해 검증.
- 낮 처치 방어 업, 밤 처치 공격 업 보정과 시간대 전환 직전(5·10·15·20·25번째 참여 카드) 균형형 처치 후 피 보상 추가 보너스는 v1.1의 보존 항목. 새 피템 구조에서 보정 대상·수치는 CHK 08에서 검증. 임의 삭제 금지.

### 4-7. 효과 시스템·HUD 슬롯

영구 효과와 임시 효과를 분리한다. **지속 효과는 전투 횟수가 아니라 턴 단위.**

| 영역 | 종류 | 적용 |
| --- | --- | --- |
| 공방 슬롯(1칸) | 공격 버프, 방어 버프, 공격 디버프, 방어 디버프 | 영구/강 임시/약 임시 |
| 피 슬롯(1칸) | 도트회복, 도트피해, 임시 최대 HP 증가·감소 | 최신 지속 효과 |
| 즉시 효과 | 즉시회복/즉시피해, 영구 능력치 증감, 스코어 획득 | 즉시 적용 후 소멸; 슬롯 미점유 |
| 미션 슬롯(1칸) | 현재 미션템 수집 개수와 품질 | 버프 없음 |

- 강/약의 초기 턴 가안: **20턴 / 10턴**. 기존의 일반 2전투·부서진 1전투 및 제단·이벤트의 2전투/1전투는 강/약 턴으로 전환한다. 실제 평균 전투 턴과 목표 밸런스로 조율. 기존 개념을 전투 수와 턴 수로 이중 계산하지 않는다.
- 공방 슬롯의 임시 효과 교체 우선순위: **종류 다름 > 등급(강/약) > 효과 강도**. 네 종류 중 다르면 수치·등급과 관계없이 새 효과로 덮어씀. 같은 종류면 상위 등급(강) 우선, 같은 등급이면 효과 절댓값이 큰 것 우선, 같은 강도면 남은 턴을 새 지속시간으로 갱신. 낮은 우선순위 효과는 기존 것을 유지.
- 영구 효과는 기본 스탯에 반영하고 사라진다. 임시 효과를 보유한 상태에서 영구 디버프를 적용해도 임시 효과와 잔여 턴은 유지된다.
- 피템은 **즉시회복·도트회복·최대 HP** 세 종류, 모두 일반템. 빛나는/부서진 등급 구분을 부여하지 않는다. 즉시회복은 슬롯을 차지하지 않고 기존 지속 효과를 유지한다.
- 피 계열 디버프는 즉시 피해, 도트피해, 최대 HP 감소로 대응 가능. 피 지속형 효과끼리 우열 없이 **최신 효과로 교체**. 상인처럼 공방과 피가 한꺼번에 발생해도 각각 슬롯에서 처리.
- 즉시회복량과 도트힐/도트피해 틱당 수치는 지정된 범위 내 자연수 추첨; 도트 범위는 즉시회복보다 작게 설계하고 틱 단위는 고정. 범위는 전투 테스트.
- 임시 최대 HP 증가 시 증가분만큼 현재 HP도 증가시키고, 감소·교체·만료 시 변경된 최대 HP를 초과한 현재 HP를 절삭한다. 영구 HP 포인트와 임시 최대 HP는 분리. 최대 HP 증감량은 가안 ±1포인트(×100 기준 ±100)부터 테스트하며 초기 적용값·감소 시 하한은 §10에서 확인.
- **유저 차례든 몹 차례든 행동이 끝날 때마다 1틱 실행.** 도트힐/피해 적용, 지속 턴 차감·만료. HP 0이면 사망이며 사망한 용사는 후속 회복으로 부활하지 않는다. 마지막 행동·보상 적용 시점 등 정확한 틱 경계는 CHK 08에서 검증.
- 전투 밖 이벤트·카드 패스·애니메이션은 턴을 소모하지 않는다. 남은 턴은 다음 전투로 이월. 보상으로 새로 받은 효과를 직전 전투 틱에서 소급 차감하지 않는다.
- 스탯·최대 HP의 하한과 표시 규칙은 §4-2/§10. 과거 0 미만이면 무효였던 규칙은 최종 하한 clamp로 변경. HUD에 남은 턴을 보여 주어 보상 선택(새 버프 vs 피)의 판단 근거로 삼는다.

### 4-8. 이벤트 6종

이벤트는 지문 → 실제 변수/코드 → 한글 선택지 → 결과 및 효과. 분기와 선택지 수, 전투 연결을 동일한 판정 구조로 구현한다. 확률은 코드에서만 읽는다. 이벤트 효과는 사전에 설정한 **수치 풀에서 가중치 추첨**한다(회복/도트의 범위 내 자연수 추첨과 구별). 효과 종류·지속 턴·확률·값을 독립 설정값으로 관리.

| 이벤트 | 선택지 | 결과·효과 |
| --- | --- | --- |
| 나무 아래 휴식 | 쉬어 간다 / 지나간다 | 성공→약초 채집→효과 랜덤 1종. 실패→제대로 쉬지 못해 피로로 HP 감소. 참여 +1, 패스 +0 |
| 수상한 상자 | 열어 본다 / 지나간다 | 성공→현재 의뢰의 빛나는 미션템 자동 획득. 실패→미믹 강제 전투; 처치 후 일반/부서진 미션템 경로 및 선택 보상. 패스 가능 |
| 떠돌이 상인 | 거래한다 / 지나간다 | 성공→공방 버프+피 버프, 사기→공방 디버프+피 디버프. 각각 수치 풀 추첨 |
| 고대 제단 | 술식 3개 / 지나간다 | 정상 축복, 조건부 부분 축복, 저주. 특수 희귀 이벤트 |
| 출렁다리 | 돌파한다 / 지나간다 | 돌파 성공→공/방 버프, 실패→공/방 디버프. 지나가기→패스 후 확률적으로 강제 배틀 |
| 안개 낀 갈림길 | 왼쪽 / 오른쪽 | 이중 랜덤: 좌우에 공방/피 계열 랜덤 배정, 선택 후 버프/디버프·효과량 추첨. 전투·패스 없음 |

#### 휴식

- 약초는 별도 카드가 아니라 휴식 성공 후 채집하는 결과. 약초 효과는 랜덤 1종만 제시. 실패(피로)로 HP 감소, 참여 게이지 누적. 이전 뇌우 표현은 사용하지 않는다.
- 약초 효과 풀, 휴식 자체 회복의 중복 여부 및 세부 성공률은 구현 전 CHK 08에서 확인(최신 흐름은 단일 약초 효과; 임의로 추가 효과 생성 금지).

#### 수상한 상자와 미믹

- 상자 열기 성공은 현재 진행 중인 미션의 **빛나는 미션템** 획득 경로. 상자만의 별도 미션템/무관한 9종 무작위 보상으로 대체하지 않는다.
- 상자가 미션인 경우 상자 관련 획득 물건은 현재 미션템으로 통일. 미믹 경로는 빛나는 제외, 일반/부서진으로 획득. 바로 열기에 성공하는 확률을 뚫어야 빛나는를 얻는다.
- 자물쇠공의 미션도 직접 열기 성공/미믹 경로 모두 의뢰품을 수집할 수 있게 한다. 동일 상자/미믹에서 미션템 중복 수집 금지.
- 미믹 자체 피해 점수는 정상 포함. 미믹 선택 보상과 미션템 자동 수집은 §4-6. **상자 탐색 미션 중 스코어용 자물쇠 등장 금지.** 그 외 미믹은 스코어템/피템 선택.
- 일반 배틀 의뢰에서 비대상 미믹을 처치했을 때의 현재 미션템 자동 수집 범위는 최신 상자 공통 원칙과 함께 CHK 08 연동 검증. 무관한 미션템이나 추가 자동 점수 지급을 임의 도입하지 않는다.
- 닫힌 상자와 미믹 그림 두 장. 실패→같은 카드 전투, 참여 1장.

#### 떠돌이 상인

- 공격/방어 선정 50:50(11/10 메모). 양수=거래 성공, 음수=사기.
- 공방 풀: +2,+1 / −1,−2. 피 풀: 각 수치 ×100, 즉 +200,+100 / −100,−200(초기 수치).
- 성공 시 두 계열 모두 버프, 실패 시 두 계열 모두 디버프. 수치별 가중치, 영구/임시 및 피 효과 유형의 구체적 배정은 CHK 08에서 테스트. 즉시·영구 효과는 슬롯 미점유, 임시 효과는 각 슬롯 교체 규칙.
- 동일 이벤트에서 두 종류 효과가 발생할 수 있도록 결과 데이터가 복수 효과를 표현할 수 있어야 한다.

#### 고대 제단

- 기존 고대 주문서 이벤트를 제단에 통합한 6종 유지. 지역 언어 술식 찾기. 제시 전 주문서/대상(공격·수호·생명)을 공개. 동일한 내용, 언어만 다른 Java·JS·TS 3개를 순서 섞어 제시.
- 현재 지역 언어 술식 정답→정상 축복. TS 지역에서 **선택한 JS 술식이 실제 TS에서도 유효한 경우에만** 부분 축복. 호환되지 않는 JS 및 그 외 오답은 저주. 단순 언어 ID만으로 TS→JS 예외를 무조건 허용하지 않음. 술식별 유효성·의도된 정답 문법 검증(CHK06).
- 정상 축복: 영구 +2 + 강 임시 +2 또는 +4(일반 이벤트 대비 2배 초기값)를 동시에 적용.
- 부분 축복: 영구 효과 없음, 정상 임시 효과의 50%, 약 임시 턴.
- 저주: 해당 스탯 영구 감소. 일반 이벤트의 −1/−2 풀을 1.5배, 즉 −1.5/−3 후보에서 확률 추첨(초기값). 임시 저주는 공통 효과 시스템으로 표현 가능하되 새 발동 규칙 임의 추가 금지.
- 생명 계열은 공방과 같은 포인트/배율 구조를 사용하되 HP 환산·영구 최대 HP 변화·임시 최대 HP/도트 효과 중 적용 세부는 CHK 08에서 테스트. 스탯 하한 적용.
- 출현 빈도를 다른 이벤트보다 낮게 설정하여 강한 효과와 균형. 구체적 가중치는 테스트.
- 결과 문구는 §5-5, 코드 판정은 §5-4.

#### 출렁다리

- 돌파는 성공/실패와 관계없이 참여 +1. 성공: 용기(공격) 또는 몸/다리 단련(방어) 임시 버프. 실패: 용기 상실(공격) 또는 부상(방어) 임시 디버프.
- 지속시간 후보: 성공 10/20턴, 실패 5/10턴(사용자가 제시한 예시/가안). 실패 지속시간 절반안은 최종 결정 전 테스트; 임의 고정 금지.
- 지나간다는 패스 +0. 이후 확률적으로 배틀에 연결되면 강제 전투 +1. 다리와 전투를 이어 연출하더라도 게이지 중복 없음.
- branch=true 유지. 확률·효과량은 설정값.

#### 안개 낀 갈림길

- branch=true. 회피/지나가기 없음.
- 등장할 때 좌우에 공방 계열 vs 피 계열을 랜덤으로 배정(1차 랜덤). 선택한 계열 내에서 버프/디버프 종류·수치·지속시간을 확률 추첨(2차 랜덤). 좌우 고정 효과 아님.
- 전투 없음, 참여 +1. 결과 상황 한 줄과 실제 수치(공격 +2, HP −100 등) 표시.
- 수치 풀은 이벤트 공통 설정, 가중치는 테스트.

### 4-9. 미션·수집·귀가·품질

- 배틀/탐색 × 노멀/하드. 시작 시 17개 풀 중 1개 랜덤 배정. 미션 리롤·3개 제시 선택 없음. 기존 의뢰자 9명, 배틀 9·탐색 8 유지(§5).
- 배틀형: 미션 대상 몹 처치 시 자동 수집, 품질은 **막타 유형별 확률 추첨(§4-6)**. 탐색형: 수상한 상자 경로의 의뢰품 자동 수집, 품질은 상자 경로. 자물쇠공도 상자 경로 수집 허용. 상자 직접 열기 성공은 빛나는 확정, 미믹 경유는 일반·부서진 한정.
- 미션 대상 몹/상자 출현 배율 초기값: 달성 전 1.5, 달성 후 0.5. 귀가 기회는 드물어야 한다는 원칙 유지. 미믹 의뢰는 상자 출현 쪽에 적용. 배율·목표 수량의 현실성은 실측.
- 달성 순간 귀가 여부를 묻고, 이후 추가 미션템을 얻을 때마다 다시 묻는다. 질문은 카드의 모든 전투/보상 선택까지 마친 뒤 카드가 버려지기 직전. 전투 중 질문 금지.
- 제출 시 요청 개수만큼 **빛나는 > 부서진 > 일반** 순서로 선정. 부서진이 일반보다 우선인 이유는 차지 도박 실패의 대가를 숨길 수 없게 하기 위함. v1.1 유지.
- 의뢰자 반응은 제출품의 최빈 품질, 동률은 **일반 > 부서진 > 빛나는**. 어떤 품질이든 요구 개수 달성 시 받아 준다. 미달성만 실패.
- HUD에는 수집/요구 개수 표시, 품질별 수집은 호버 정보에서 확인(§6).
- 30번째 참여 카드에서 달성하면 귀가 질문 없이 컴플릿. 30장 완주 시 미달성이면 노멀. 수집 초과분도 점수 공식에 반영.

### 4-10. 점수

- **최종 스코어 = 몹에게 준 실제 피해 총량 + 선택한 스코어템 점수 + 미션 완료 보너스.**
- 오버킬 제외, 몹에게 들어간 카운터 반사 피해 포함, 미믹 피해 포함. 오버킬과 반사 피해의 중복 기록 금지.
- 미션 완료 보너스는 미션 달성 후 귀가 또는 30장 완주+달성일 때만 적용. 사망·시간초과·미달성은 0.
- 보너스 공식(기호 분리):

```txt
missionBonus = requiredCount × (shiningCount × x + normalCount × y + brokenCount × z) × k
```

- requiredCount: 의뢰 요청 개수. shiningCount/normalCount/brokenCount: 이번 판 수집한 해당 미션템 전체 개수(초과분 포함).
- x,y,z: 등급별 점수 계수, k: 환산계수. 테스트 프로그램 설정값으로 분리. 계수 수치/최종 정수화는 CHK 08에서 확정.
- 기존 v1.1의 품질은 점수에 영향 없음/노멀·하드 고정 보너스 규칙을 위 공식으로 교체. 엔딩 품질 판정은 별도 유지.
- 미믹 스코어템 점수 = 기준 점수 × 등급 계수. 일반/부서진만, 선택 획득 시 1회 적용 후 소멸. 과거 메모의 100/50은 참고 초기 후보이며 빛나는 150은 현행 드롭 대상 아님. 기준값과 계수는 테스트.
- 스코어 상한 없음, 플랫폼 max_score 비워 둠. 높은 점수가 상위. 최종 점수 1회 제출.

### 4-11. 종료·엔딩·결과

| 종료 조건 | 엔딩 | 미션 보너스 |
| --- | --- | --- |
| 달성 후 귀가 선택 | 컴플릿: 품질별 의뢰자 반응+크레딧 | 지급 |
| 30장 완주+미션 달성 | 컴플릿 | 지급 |
| 30장 완주+미션 미달성 | 노멀: 미달성 반응 | 없음 |
| HP 0(전투/이벤트/도트 포함) | 게임오버(객사) | 없음 |
| 시간 종료 | HP 0으로 처리, 게임오버 | 없음 |

- 어떤 종료든 해당 시점에서 판 종료, 그때까지 점수 한 번 제출.
- 미션템 0개 대사 분기:
  - 중간 게임오버: "빈손이라니! 이럴 거면 의뢰는 왜 받은 건가?"
  - 30장 완주: "빈손이라니! 대체 뭘 하고 돌아온 건가?"
- 요구량 미달(1개 이상): 실제 요구 개수를 변수로 넣어 "내가 필요한 건 {요구개수}개였는데… 아쉽군." 의뢰자 말투에 맞게 표현. 0개는 위 대사 우선. 게임오버에 반응을 표시하더라도 게임오버 분류·보너스는 변경하지 않는다.
- 컴플릿: 품질별 의뢰자 반응 및 크레딧. 엔딩은 텍스트로 구성.
- 결과 화면(앱 내부): 최종 점수와 총 피해량 구분, 처치 수, 참여 카드 수, 크리티컬·카운터 횟수, 최종 스탯, 미션 달성 여부/품질별 수량. 획득 목록에는 일차·시간대·몹/이벤트·획득 아이템·수치 기록(예: 1일차 낮 · 돌껍질 거북에게서 거북 등껍질). 컴플릿 통계와 목록은 크레딧처럼 흐름.
- 기존에는 결과 화면 기록을 판 밖에 저장하지 않는 원칙. v1.2의 어드민 선택형 밸런스 분석 수집은 별도 분석용 기록이며 사용자 인벤토리/진행 저장이 아니다(§8).

## 5. 콘텐츠 데이터

### 5-4. 중립 코드·학습 문법 (CHK 06 개발 병행)

- 중립 데이터 한 벌을 Java·JS·TS로 렌더링. 지역별 카드 3벌을 따로 만들지 않는다. 상황 실제 값, 조건, 확률과 실제 판정의 원천 데이터를 일치시킨다.
- 카드 구성: 지문 → 코드 → 한글 선택지. 성공률은 선택지에 표시하지 않고 코드 안에서 보여 준다(예: `Math.random() < 0.3`). v1.1 `rate = 80;` 형식은 선행 구현 기준. v1.2 보류 메모의 실확률 방식으로 조율하되 실제 렌더링·판정 연결은 CHK 06에서 검증하고 변경 명세 작성.
- if, switch(정확히 2케이스, 전체 경우를 포괄할 때 default 없음, break 필수) 기본 유지. if/else 필수화는 11/10 메모의 검토안으로 실제 코드의 모든 경로가 유효한지 CHK 06에서 확인. 한 줄 분기, 간결한 결과 대입. 6줄/논리연산 3개는 실패 기준이 아니라 QA 검토 기준.
- Java 동등/비동등 비교 `==`, `!=`; JS/TS `===`, `!==`(11/10 메모 방향, CHK 06 검증). if에는 숫자·boolean, 문자열은 switch라는 기존 학습 범위를 보존; 문자열 비교를 확장할 경우 Java .equals() 등 언어별 정확성 검토.
- 변수 선언 예:

| 타입 | Java | JS | TS |
| --- | --- | --- | --- |
| 정수 | int hp = 45; | let hp = 45; | let hp: number = 45; |
| 소수 | double rate = 0.5; | let rate = 0.5; | let rate: number = 0.5; |
| boolean | boolean rotten = true; | let rotten = true; | let rotten: boolean = true; |
| 문자열 | String time = "NIGHT"; | let time = "NIGHT"; | let time: string = "NIGHT"; |

- Java 정수 나눗셈은 (double) 형변환. 결과변수 타입은 실제 값에 맞게(정수 rate였던 선행 구현 int를 무조건 오류로 분류하지 않음). 연산자 우선순위와 괄호 규칙 보존.
- 모험 카드에는 답을 알려주는 결과 주석 금지. 전투 카드의 명중률 주석만 영어로 짧게 허용. 주석은 해당 줄 끝 정렬.
- 술식: 같은 내용, 언어 고유 문법이 구별되는 3개. Java의 String, .equals(), System.out.println, 람다 ->, for-each; JS 화살표 함수/console.log; TS 타입 표기/interface 등을 후보로 사용. 정답은 지역의 의도된 언어; TS에서도 유효한 JS 술식 부분 축복은 개별 술식으로 검증. 동일 표현만으로 언어 구분 불가능한 샘플은 피한다.
- 카드 조건/확률과 실제 결과가 동일해야 하며 세 언어별 출력 정답, 실제 유효 문법, 현재 변수 대입, 타입, 2분기 전체 도달, 길이/논리 연산 수, 숨은 확률/결과 불일치를 QA한다. 랜덤의 랜덤 분기와 수치 풀 추첨의 코드 표현 범위도 함께 결정.
- 기존 검증 페이지의 코드 샘플·괄호·정수/소수 테스트는 삭제하지 않고 변경 규칙에 맞춰 정답을 갱신하고 검증한다.

### 5-6. 데이터 구조와 검증

- 몹: 기본 ID/이름, 활동 시간, 유형, 기본 스탯 범위, 지역별 이름/팔레트/스탯 보정, 미션템 ID, 등장 방식, assetId.
- 미션템: 기본 ID/표시명/부자재명/원천 몹/그림/미션 장면, 등급. 전투 버프를 자동으로 발동시키지 않음.
- 보상템: 효과 종류/등급/수치 또는 풀/지속 턴/점수 계수. 미션템과 용도를 분리.
- 이벤트: id, 장소/장면/아이콘, 상황 지문, 중립 코드, 선택지, 조건/가중치 결과와 문구, 하나 이상의 효과, passable/branch.
- 미션: id, clientId, kind, difficulty, targetMobId 또는 targetItemId, count, dialogue. 의뢰자 데이터는 name, itemId, sceneAssetId, endings 등을 공유. 실패는 요구량과 종료 유형에 따라 동적 출력.
- 검증: 기존 11개 연결 검사(에셋 존재·픽셀 파일 1그림·상호 참조·미션/의뢰자·이벤트 6종 등) 보존. v1.2에서 역할이 달라지는 item.reward 검사 등은 의미에 맞춰 갱신(단순 삭제 금지).
- 추가 검수: 필수 데이터 비어 있음, 9몹/17미션/9의뢰자/6이벤트, 밤 배틀 미션 수량≤3, 스탯 범위/지역 변형, 수치 풀·가중치·등급·지속 턴, 이벤트 선택과 효과, 수집/보상/점수 중복, 코드 실제 유효성. 기존 선택 필드는 선행 단계에서 의도적으로 비워둔 것이므로 미구현과 오류를 구분.
- 콘텐츠 최소 수량은 랜덤이 성립하는 최소. 기존 구현 17종 미션은 축소하지 않는다.

## 6. 화면 및 UX

### 6-1. 공통·카드 길

- **800×500 고정 비율**. 플랫폼 iframe 모달로 제공. HUD·버튼·카드·모달은 해당 프레임 안에 배치한다.
- CSS perspective + preserve-3d로 길 바닥을 눕히고(rotateX) 카드를 깊이 방향으로 줄지어 세운다. 뒤쪽 카드 2~3장.
- 맨 앞 카드가 제자리에서 떠오르며(rotateX 0, 살짝 확대) 같은 위치에 모달 페이드인. 카드가 대열 이탈하거나 모달로 변신하지 않는다.
- 참여 종료 카드 회전·축소·투명해지며 버려짐, 대열 전진. 패스 카드는 옆으로 비켜나 다음 카드가 접근(게이지 미증가를 시각적으로 구분).
- 연출 길이는 고정 설정값, 연출 중 입력 잠금. 전투 연결 이벤트는 필요 시 같은 모달 안에서 이어 연출.

### 6-2. 모험·배틀 모달

- 모험: 지역/장소 이름 → 지문 → 코드 → 선택지(성공률 별도 표시 없음) → 결과 문구·효과.
- 배틀: 같은 카드가 떠오른 상태로 턴 교대 → 보상 선택 → 카드 버림. 전투 전 일반 조우/잠든 몹 선택과 강제 전투를 구분.
- 매 행동 진행에 맞춰 현재 코드·HP·몹 차지 상태를 갱신. 양쪽 명중률은 공격자 기준. 예(기존 명중률 코드의 표시 의도 유지):

```javascript
let heroHp = 820;
let monsterHp = 640;
let monsterCharged = true;
let heroHit = heroHp / (heroHp + monsterHp);       // hero hit: 56%
let monsterHit = monsterHp / (heroHp + monsterHp); // monster hit: 44%
```

- 버튼: hero.attack(), hero.defend(), hero.charge() (차지 중 charge 비활성). 전투 중 도망 없음.
- 행동 연출: 코드 갱신→현재 행동→판정(헛스윙·빗맞힘·평타·크리티컬)과 피해 숫자→HP 바 및 틱/HUD 갱신→상대 차례. 승리 후 자동 미션 수집 및 보상 선택 2개.
- 전투 이펙트 원본 64×64, 팔레트·움직임 재사용. 공격은 베기 자국(차지공격은 크게), 차지는 여러 반짝이가 한 곳으로 모여 사라짐, 버프/축복은 반짝이가 퍼짐(공격 금빛·방어 푸른빛·HP 초록빛).
- 몹 효과는 몹 그림 위. 용사는 1인칭으로 화면 기준 표시. 피격은 가장자리 붉은 비네트, 용사 차지·버프 위치는 구현 중 결정.
- 위기 연출: 양쪽 각각 HP가 처음 10% 이하로 떨어지고 생존했을 때 1회. 몹 0.2초가량 붉은 틴트, 용사 HP 바 강조. 피격 비네트와 구분.

### 6-3. 환경

- 낮밤 참여 5장, 지역 참여 10장. CSS 테마·팔레트/밤 필터 전환, 새 지역명 크게 표시.
- 지형지물은 길 양옆 페이퍼아트처럼 일으켜 세움. 카드 전진과 같은 거리로 이동, 지나간 소품은 뒤로 재사용. 양옆 3~4개씩 총 6~8개 기준. 감싼 요소 transform으로 이동(재렌더 방지).
- 배율·팔레트·에셋 표현은 §2. 기존 렌더체크 10탭은 개발 검증 도구로 보존, 실제 런타임 화면은 별도 구성.

### 6-4. HUD

- HP 현재/최대, 공격·방어, 참여 게이지(30), 실제 시간 카운트다운, 아이콘 3칸(미션/공방/피).
- 미션 아이콘은 **일반 등급 그림 고정**, 수집/요구 수량 배지. 버프인포(호버)에 빛나는·일반·부서진 각각 기존 등급 이미지와 개수. 수집량에 따라 최고 등급 아이콘으로 교체하지 않음. 아이템 그림은 기존 렌더러와 표시 배율 조절로 재사용.
- 공방·피 슬롯: 임시 효과의 아이콘/남은 턴 표시, 호버에 종류·효과·잔여 턴. 영구/즉시 효과는 등록하지 않음. 모바일 등 호버 불가 환경에서 동등한 정보 접근 방식은 실제 UX 검증.
- 각 슬롯의 교체·만료 즉시 UI 반영. 도트/최대 HP 효과가 끝나거나 바뀔 때 HP 바·수치 정합성 유지.
- 실제 수치와 표시값 반올림이 분리될 경우 판정 코드는 실제 값을 올바르게 설명해야 한다(CHK06/08).

### 6-5. 도움말

- 타이틀의 도움말 버튼, 규칙 요약 1장. 조작·공격/방어/차지, 차지 다음 행동, 전투 전 도망, 패스/게이지, 미션/귀가, 시간·엔딩.
- 공략(미션 품질, 드롭·미믹 경로 득실, 보상 보정, 희귀 이벤트, 출현 배율 등)은 설명하지 않는다. 발견·공유하는 재미 유지. 최종 문구는 수치 조율 후 작성.

## 7. 플랫폼 연동

- Vite base 상대경로, dist 커밋 규격 유지. 공식 SDK 계약에 맞춰 iframe에서 실행. 상위 메인스펙과 02_01 최신 승인 규칙 확인.
- 세션 시작: 스탯 굴림 및 미션 수락 후 출발 순간. 점수 제출은 컴플릿·노멀·게임오버 모두 1회. 미리보기/승인 대기에서는 테스트 모드.
- max_score 없음. 높은 점수가 상위. 세션 만료 시간은 전체 게임 제한 N + 여유. 조기 귀가/게임오버로 플레이 시간이 다양하므로 이상값 검사에 반영.
- 실제 시간 기준 타이머: 시작 시각 + 제한 시간 − 현재 시각. 탭 전환·렌더 정지로 시간을 벌 수 없음.
- 플랫폼 공식 점수 제출과 분석 데이터 수집은 별도. 메인 플랫폼 어드민/서버의 계약 변경은 사용자 승인 없이 구현하지 않는다. SDK·세션·권한·분석 데이터 수집 경로는 CHK 12 병행 검증.

## 8. 밸런스 테스트·리밸런싱 시스템 (CHK 08/12)

### 8-1. 확정 목표

- 전투 엔진 개발과 동시에 **실제 플레이 데이터 누적·통계 기반 밸런스 분석 프로그램**을 제작한다. 단순 고정 표본 시뮬레이션만으로 대체하지 않는다.
- 어드민에서 분석용 플레이 데이터 수집 ON/OFF. 실제 가동 중에도 데이터를 확보하여 리밸런싱 가능.
- 분석 프로그램은 정해진 계산·통계 로직으로 목표값과 비교해 조율 변수의 적정 후보값을 산출. AI/LLM 판단 불필요. 자동으로 서비스 설정을 덮어쓰는 기능은 확정하지 않았으므로 검토/승인 후 설정 조정.
- 게임 규칙/조율 변수/수집 데이터/계산 결과를 분리. 고정된 공식은 유지하고 계수와 값만 조율. 이전 설정과 변경 후 결과를 비교할 수 있도록 설정 및 밸런스 버전을 식별.

### 8-3. 구현·회귀 검수 원칙

## 11. 기존 감수·선택 확장·홀딩

### 11-0. 감수 사항

- 랜덤 카드/미션에 따른 운의 차이는 오락실 원칙("억울하면 네가 1등 해라")으로 수용.
- 앱 파일의 카드/정답 데이터 열람 가능. 점수 조작 완전 방지는 기존 MVP 범위 밖.
- 반복 플레이에서 같은 카드·몹 정보를 익히는 것은 숙련 보상.
- 세션 이전 무제한 스탯 리롤은 정당한 전략.

### 11-1. 선택 확장(기준선 변경 불가, 승인 필요)

- 실시간 이동, 카드→모달 변신 연출.
- 스탯 기반 선공/중첩 차지(현재 확정 선공 및 연속 차지 금지 규칙 변경이므로 별도 승인 없이는 구현하지 않음).
- 몹 타입별 행동/방어 패턴, 지역 전용 카드/밤 전용 이벤트, 거리별 공기원근·효과음, 첫 배틀 도움말.
- 점수·판 길이·종료 조건 및 확정 룰 변경은 재량 아님.

### 11-2. 홀딩(개발 확정 아님)

- 3항연산자 등 if/switch 외 표현.
- 상자 외 탐색 미션(약초 등).
- 추측형 미션(힌트 조건식, 하드 후보 2마리 이하, 미션 리롤 없음에 맞춘 난이도 보완).
- 조건부 출현 이벤트/플래그, 클라이맥스 보스.
- 소비 아이템 보관·인벤토리, 판을 넘는 도감, 메타 성장.
- 결과 텍스트 복사(iframe 클립보드 권한 확인).
- 위 홀딩은 삭제가 아니라 보류 상태로 보존.

**종결 상태:** v1.2는 통합 기획 기준 문서이며, 실측 수치·기술적 경계는 §10의 추적 항목으로 관리한다. 이전 메인스펙 삭제 여부는 사용자가 로컬에서 결정한다. Notion 원본 및 기존 작업명세는 보존한다.

### 12-3. v1.2 정정 이력(2026-11-12, 버전 유지)

- **정정 사유:** v1.2 통합 과정에서 미션템과 전투 선택 보상을 분리하며, 미션템 품질에 적용해야 할 막타 기반 확률 추첨이 종전 차지공격 기록의 확정 판정으로 남아 있던 정합성 오류를 정정한다. 새 획득물이나 신규 시스템을 추가하지 않는다.
- **적용:** 배틀 미션 대상 몹 처치로 자동 수집한 미션템의 품질에도 전투 선택 보상의 등급과 같은 막타 유형별 가중치를 적용한다(기본 2:5:3, 충전/반격 크리티컬 3:4:3, 빗맞힘 2:4:4). 차지 크리티컬은 확률을 높일 뿐 확정 획득이 아니다.
- **별도 경로 보존:** 수상한 상자 직접 열기 성공의 빛나는 미션템 확정 및 미믹 경유의 일반·부서진 한정 규칙은 유지한다. 미션템 자동 수집·버프 없음, 선택 보상 별도 지급, 피템 등급 미적용 원칙도 유지한다.
- **후속:** 작업 03·04/CHK 08 작업명세에서 실제 등급 판정·기록·추첨기 연동을 교정하고 검증한다. 전투 밸런스·확률 조정은 별도 승인 대상이다.
