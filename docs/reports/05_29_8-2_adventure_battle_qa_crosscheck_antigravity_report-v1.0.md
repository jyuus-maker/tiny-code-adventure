## 3. 주요 주의 사항 및 기획 충돌 교차검증 (핵심 요약)

### 1) I-05 (보상 등급 막타 충전 여부 판정 오류)
- `BattleModal.tsx:272`: `wasLastHitCharged = lastHeroRes?.action === 'attack' && qualityLog.hasChargeCrit;`
- **실제 동작**: 막타 자체가 충전 공격이었는지가 아니라, **전투 전체에서 충전 크리가 한 번이라도 있었는가**를 검사하고 있음.
- **해결 방안**: 엔진의 `ActionResolution`에 `wasCharged` 플래그를 추가하여 막타 시점의 차지 여부를 정확히 전달하도록 수정 필요 (S-01 제안과 일치).

### 2) I-06 (도망 성공률 clamp 불일치 — 기획 충돌)
- 판정식(`encounter.ts:29`): `heroHp / (heroHp + mobHp)` (clamp 없음)
- 화면 표시(`BattleModal.tsx:460`): `calcHitRate(heroHp, mobHp)` (clamp 10%~90% 적용)
- **현상**: 체력비가 극단적일 때 화면에는 `도망간다 (확률: 10%)`로 표시되나 실제 성공률은 4.8%로 판정되는 괴리 발생. 도망 확률에 명중률과 동일한 clamp를 적용할지 기획 확정 필요.

### 3) I-04 (귀가 질문 재질문 조건)
- `gameState.ts:373`: 미션 달성 상태면 새 미션 아이템 수집이 없어도 모든 카드 퇴장마다 귀가를 질문함. 명세(달성 시 1회 + 추가 수집 시마다)에 맞게 이전 수집 수량과 비교하는 조건 보완 필요.

### 4) I-07 (선택지 문구에 성공률 텍스트 직접 표기)
- `BattleModal.tsx`: 버튼에 `(확률: N%)`, `(성공률 높음/낮음)`을 직접 표기하고 있음. 중립 코드 카드로 표현하는 기획(CHK 06)과의 연계 조율 필요.

## 4. B단계 전투 밸런스 분석에 대한 교차검증 의견

검수보고서 5절의 시뮬레이션 분석 결과는 현재 코드 수식의 특성을 매우 정확하게 짚어냈습니다.

- **원인 분석**:
  - 용사 체력(평균 1,000) 및 몹 체력(700~1,300) 대비, 용사 ATK(5~20)와 몹 DEF(6~16)가 겹쳐 있어 `ATK ≤ DEF`인 상황이 빈번함.
  - 현재 수식(`engine.ts:67`)에서 `baseDiff = Math.max(0.1, ATK - effectiveDef)`로 인해 방어가 높은 몹에게는 **평타 1, 크리티컬 2, 차지 크리티컬 3의 바닥 데미지**만 들어감.
  - 이로 인해 평균 전투 턴이 **150~250턴**에 달하고, 300턴 상한 도달(미완료 검열) 비율이 50%를 상회함.
- **방향성 동의**:
  - 검수보고서 5-7절의 후보 비교(G안: `damageScale 25` + `defenseRate 0.7` 등)처럼, **피해 스케일 상향**과 **방어 적용률 조정**, 혹은 **몹 DEF 기준치 조정**을 통해 평균 턴 수를 적정 수준(10~20턴 내외)으로 압축하는 밸런스 조율이 반드시 수반되어야 합니다.
